## Description

AWS infrastructure costs have grown 340% over the past two years while our workload profile has remained relatively stable. We are currently spending $42K/month on EC2, RDS, and S3 alone. Preliminary analysis shows that equivalent bare-metal servers in a colocation facility would cost roughly $8K/month after amortization, saving approximately $400K annually.

This opportunity evaluates migrating our primary compute and storage workloads from AWS to self-hosted servers in a colocation data center, while keeping AWS as a disaster recovery and burst capacity target.

## Impact

- **Cost**: Projected annual savings of $400K (76% reduction in infrastructure spend). Payback period for hardware investment is approximately 8 months.
- **Performance**: Bare-metal servers eliminate the noisy neighbor problem. Internal benchmarks show 2.3x better P99 latency on dedicated hardware vs comparable EC2 instances.
- **Control**: Full control over hardware lifecycle, firmware updates, and network topology. No dependency on AWS region availability or pricing changes.

## Success Metrics

- Reduce monthly infrastructure cost from $42K to under $12K within 6 months of migration
- Maintain 99.95% uptime SLA during and after migration
- P99 API latency equal to or better than current AWS baseline
- Complete migration of all production workloads within 9 months

## Non-Goals

- Migrating away from S3 for object storage — keep S3 for backups and static assets
- Building a private cloud platform (OpenStack, etc.) — use simple container orchestration
- Multi-datacenter redundancy in phase 1 — DR stays on AWS

## Alternatives Considered

| ❓ | Option | Rationale |
|---|---|---|
| ✅ | Colocation with owned hardware | Best cost/performance ratio; full control over hardware lifecycle |
| 🚫 | Hetzner/OVH dedicated servers | Lower initial cost but less control over network and no local hands |
| 🚫 | AWS Reserved Instances + Savings Plans | Only 30-40% savings vs on-demand; still significantly more expensive than self-hosted |
| 🚫 | GCP/Azure migration | Cloud-to-cloud migration has high effort with marginal cost improvement |

## Risks

- **Migration downtime**: Moving stateful services (PostgreSQL, Redis) requires careful planning to avoid data loss. Mitigation: use logical replication for zero-downtime database migration.
- **Operational burden**: Self-hosted infrastructure requires on-call for hardware failures. Mitigation: maintain spare parts inventory and IPMI/BMC remote management.
- **Scaling limitations**: Bare-metal scaling is slower than cloud auto-scaling. Mitigation: keep AWS burst capacity available and use it for traffic spikes.
- **Single point of failure**: Single datacenter introduces geographic risk. Mitigation: keep AWS DR environment warm with async replication.
